## 一、接手：先确定可以做什么

在仓库根依次执行：

```powershell
git status --short
git log --oneline -5
node tests/env-check.mjs
node tests/run-ci.mjs --status
```

读取现状待办、feature-status、README 顶部及对应切片计划，加载项目 orientation、code-navigation 和相关子系统技能。开工记录四件事：本轮属于哪个 P／M 切片、验收口径在哪里、已有改动归属、需要哪些技能。

- 有浏览器作业：只做代码阅读、设计和文档；不启动第二个验收、生成器或 `check-docs --regen`。
- 有未提交实现：先核对它已经做到哪，不重复实现，不覆盖他人改动。
- 台账中断且代码树未变：保留进度并续跑；不能从头重跑，也不能把中断写成产品失败。
- 缺少验收口径：先写切片卡，再改代码。

## 二、先收已有证据，再开新实现

1. 旧树结束后，核对旧树台账、日志末行和退出记录；在旧树 output 保存带 treeHash／时间的台账与退出副本，保留日志位置。
2. 确认旧任务及其浏览器子进程已结束，主树源码、测试与单文件仍对应原哈希。
3. 在主仓库重新绑定计划任务，然后启动续跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests\gate-detached.ps1 -Action install
powershell -NoProfile -ExecutionPolicy Bypass -File tests\gate-detached.ps1 -Action start
node tests/run-ci.mjs --status
```

4. 主树长跑期间冻结源码、测试与产物；可以准备下一切片文档，不在这棵冻结树上提前落码。
5. 若出现产品失败，先保留失败证据并修复；修复改变 treeHash 后按新树验证，不沿用旧树进度。完整 CI 结束也不等于 M4 人工验收完成。

## 三、按小切片推进，不一次铺开所有系统

| 次序 | 本轮交付单元 | 进入下一项前应拿到什么 |
| --- | --- | --- |
| 1 | 人物页补全 | 旧六人与新十一人无重复；已知身份、好感、去向与事件状态真实；旧档和窄屏专项证据 |
| 2 | 人物日程样板 | 先赫莎、娜汀、维克；工作、休息、雨天与主线优先级可解释，真实走到本人且服务不中断 |
| 3 | 其余日程 | 伊文、鲁恩、奥蕾尔、伯兰、科林、艾诺每批 2—3 人；弥拉另补日常，保留迁居事实 |
| 4 | 其余九人关系事件 | 每批 2—3 段，从总规唯一正文接入；可拒绝、可回看、不重复奖励、不改写主线责任 |
| 5 | 一种果树的完整循环 | 种植、成长、照料、季节产出、采收、离家委托与存档成立后再扩品种 |
| 6 | 季节与家庭生活 | 先一个季节活动及一次邻里回访；再扩建、装饰、每周集市，各自有入口、成本和持续结果 |
| 7 | 成长与长计划 | 天赋按实际用途分批开放；14／28 天计划与逐日结算、照料、取消恢复一同验收 |
| 8 | 长期职业制度 | 每次一个职业闭环；银行家危机、市政任期、有限封授分别立项 |
| 9 | 新国家与第二部 | 第一部发布证据、人工反馈与新篇章依赖核定后再开工 |

每项完成一个可验收单元即可同步记录；不要求把整张路线图全部完成后才交付。真实发布阻断缺陷优先于新增内容。

## 四、每轮都填一张切片卡

```text

验收：套件名、断言清单、源码／单文件层、自然入口范围
```

## 五、审查与实现放在同一个闭环

1. 用 `rg` 重新定位代码符号，读取入口→条件→状态写入→保存／归一化→展示的完整链；旧行号仅作索引。
2. 把发现分为：已确认缺陷、规划未实现、证据不足、取证问题。可疑缺陷先找正常玩家触发路径，无法复现的只登记风险。
3. 明确正文与规则。关系事件先写总规唯一分场稿；经济功能先写资金来源、扣减与幂等条件；地图先查站位、碰撞和出口。
4. 最小落码，复用现有注册表和账本。`SCHEMA_VERSION` 保持 2；旧档只补默认值，不补完成事实。
5. 增加真实输入专项与必要旧档 seed。读式断言检查结果；场景、时间、好感等夹具在文件头声明，不把夹具测试称为自然入口。
6. 审查实际差异，确认无无关格式化、重复人物、绕过门槛、重复奖励及遗失存档字段。

`game.js` 同时只允许一个写者；任何浏览器作业及单文件重建串行。若安排独立只读审计，其范围限证据与代码阅读，不改文件、不跑浏览器。

## 六、先专项，后冻结全量

日常先跑受影响的最小专项；新套件接入 CI 浏览器层，产物敏感套件同时接入单文件层。长程自然路线仅跑源码层；重叠自然路线保留覆盖更完整的一条。

```powershell
node --check game.js
node tests/build-single-file.mjs
node tests/run-ci.mjs --dump-steps
# 用本轮真实套件名替换示例
node tests/run-ci.mjs --only=run-ms1-people-journal
```

示例人物页套件尚未创建，不可提前记为已跑。检查实际命中的源码／单文件阶段及汇总，不以命令成功启动代替验收。

专项通过后重建并核对单文件零漂移，再跑快速层。冻结源码、测试与产物后，按第二节的脱会话方式跑一次完整 CI；新增套件后的总阶段数以 `--dump-steps` 为准，不硬写 124。全量期间不运行会启动浏览器的文档生成器。

## 七、失败、等待与续跑

| 现场 | 动作 | 对外记录 |
| --- | --- | --- |
| 规则或正常入口断言失败 | 保留日志，复现并修实现；树变后重新验证 | 在做（未验证），注明触发条件和修复范围 |
| 测试读取错误或夹具越界 | 修取证方式，保持产品要求；重新跑受影响项 | 写清为什么是取证问题及新证据 |
| 环境拒绝、进程消失、无末行 | 检查心跳、进程与退出信息；同树续跑 | 分层通过 x/N，注明原因与下一步 |
| 已有浏览器作业 | 等待并处理独立只读／文档工作 | 不并行重启，不另造通过结论 |

连续两次非产品中断必须确认并修正 OS 级执行方式，再续跑；连续三次按分层证据交付，禁止从头反复重跑。全量必须由 `gate-detached.ps1` 执行，不能交给会随会话退出的后台 job。

每 15—20 分钟或每个阶段簇报告 x/N、ETA、风险与当前可交付单元。中断交接写清树、目录、最后阶段、心跳、日志和续跑入口，不只写“继续等”。

## 八、验收、文档与提交

完整 CI 判据必须同时满足：同一 treeHash 的全部阶段通过、对应日志末行完成、对应完整退出记录为成功。过滤运行即使 exit=0 也不能替代完整轮。切片级验收则必须逐条满足事先声明的验收口径，并明确完整回归未完成的边界。

浏览器空闲后，同步现状待办、对应计划、README 和生成状态表；保留状态表人工节，不手改生成区。执行：

```powershell
node tests/check-docs.mjs --regen
git diff --check
git status --short
```

纯文档轮不重建游戏、不额外跑全量 CI；静态机检未覆盖的文档另核链接、代码锚点与状态。若因已有浏览器作业未执行 `--regen`，明确保留该门槛，不宣称完整验收。

确认截图是否属于本轮生成噪声后再处理，不能批量还原接手前已有的修改。按代码／测试／文档／产物分笔提交，只包含本轮文件；中文提交信息用 UTF-8 无 BOM 文件配合 `git commit -F`。未经明确要求不推送；报告本地与 origin 的领先笔数及是否刷新过远端。

```text
本轮结果与状态：
实现范围与原因：
逻辑／界面证据：树、套件、项数、日志、退出记录
自然入口证据：起点、真实输入范围、夹具及未覆盖部分
人工验收：设备、人数、有效时长；没有则写未测
完整 CI：同树 x/N、末行与退出证据；未收口原因及续跑位置
文档校验：静态／regen 分别记录
提交与工作区：提交号、剩余改动、领先笔数、是否推送
下一轮唯一首项：具体切片及第一条操作
```

实体手机、至少五位初见玩家和有效游玩时长独立记录，主持人提示、失败与中途退出不得删去。自动化通过不能替代三类人工结果；本流程编写不改变它们当前“未测”的状态。

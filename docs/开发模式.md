# 开发模式与项目技能

更新：2026-10-22

本仓库配了一套 **DSH Agent preset（开发模式）＋ 项目技能 ＋ 项目契约**，让 AI 代理在这个仓库里按项目既有纪律工作：
先读证据、按切片交付、守住不变量、不把提案当已实装。

## 一、组成

| 位置 | 是什么 | 生效方式 |
| --- | --- | --- |
| `.dsh/agent-preset/` | DSH bundle（`@local/dsh-xinglu-preset`），声明 Agent preset「苔芽农场开发」（id `xinglu-dev`） | 已安装进当前 DSH profile；**改完要重装**，新会话才生效 |
| `.dsh/skills/` | 10 个项目技能（`xinglu-*`） | 文件系统技能目录，改完立即热更新（新一步的 skill 目录会刷新） |
| `AGENTS.md` | 项目契约（所有会话自动加载） | 编辑后新一次读取/新会话生效 |
| `docs/开发模式.md` | 本说明 | — |

模式里包含：项目 persona（先事实后动手、切片闭环、证据三层、硬约束、技能路由）、`AGENTS.md` 自动加载、
Windows `pwsh` 与文件工具、`skill` 加载器、计划模式（项目定制版）、目标/todo、子代理与 workflow、后台 job、web、present。
`plugin_manager` 在模式内保持关闭（与 Standard 一致），避免在业务会话里误改 profile。

## 二、怎么用

1. **选择模式**：新建任务时在模式选择器里选「苔芽农场开发」；或在 Settings 的 Agent Preset 列表里把它设为新任务默认。
   已存在的会话**不会**自动切换模式（保留创建时的组合）。
2. **权限建议**：跑 Playwright / 完整 CI 的会话建议用 Full access 或对本机放行；Windows 沙箱下 Playwright 可能
   `spawn EPERM`，那是环境拒绝，不是回归。
3. **开工顺序**：会话开始后先加载 `xinglu-project-orientation`（它会告诉你先读哪几份文档、按 P0—P4 选题），
   再按任务加载子系统技能（钱/存档/场景/剧情/渲染/UI/套件/收口）。
4. **不要**在模式里直接跑完整 CI 前改代码；完整 CI 必须在冻结产物上串行跑，通过判据是末行「两层全部通过。」+ 退出码 0。

## 四、维护

### 改技能

直接编辑 `.dsh/skills/<name>/SKILL.md` 即可，下一步会刷新技能目录。约定：

- 目录名 kebab-case，`SKILL.md` 首部 YAML frontmatter 必须有 `name` 与 `description`（description 写清触发条件）。
- 正文 < 8192 字符（超过会被 tool-result pruner 截断）；长表格/配方放 `references/`，用相对路径引用。
- 数字与行号是快照，改了代码后用 grep 复核；跨技能重复的事实放到 `xinglu-code-navigation`，别两处各写一份。

### 改模式（preset）

模式是一个 bundle patch：`.dsh/agent-preset/cordis.patch.yml`。改完后必须**重新安装**并让新会话生效：

```
plugin_manager(action="install_bundle", target="C:\\Users\\22079\\Documents\\ChatGPT\\星露谷\\.dsh\\agent-preset")
```

（也可以在 Web 的 Plugins 页重新安装该本地 bundle。）验证：

- `plugin_manager(list_bundles)` 中 `@local/dsh-xinglu-preset` 为 `enabled/installed/removable`，rows 为 `preset-xinglu-dev`；
- `cordis_inspect_query(host, Config, listConfigs, {name:"@deepseek-ai/dsh-agent-preset"})` 中出现 `include:preset-xinglu-dev`；
- 新建一个会话选择「苔芽农场开发」，确认 persona/技能/工具都可用（现有会话不会被改写）。

卸载：`plugin_manager(action="remove_bundle", target="@local/dsh-xinglu-preset")`。项目文件不影响已运行的会话。

### 改项目契约

`AGENTS.md` 会自动注入所有会话；它和技能冲突时以更具体的技能/直接用户指令为准。改动后请同步本文件与技能里的引用。

## 六、故障排查

| 现象 | 处理 |
| --- | --- |
| 模式选择器里没有「苔芽农场开发」 | 确认 bundle 已安装且 preset 行激活；重装 bundle；刷新页面 |
| 新会话没有 persona/工具 | 可能选错模式（现有会话不切换）；新建会话再选 |
| 技能列表里少了项目技能 | 确认会话工作目录是仓库根（`.git` 所在处）；技能在 `.dsh/skills/`，只扫一层目录 |
| 技能内容改了但会话没变 | 技能目录会在下一次 pre-step 刷新；已加载过的正文是历史消息，需要重新加载 |
| preset 改了但没生效 | 必须重装 bundle 且新建会话；现有会话保留旧组合 |
| Playwright 报 `spawn EPERM` | Windows 沙箱拒绝命名管道，换 Full access；不是代码回归 |
| 完整 CI 看起来"绿" | 只认末行「两层全部通过。」+ 退出码 0；中断/仍在增长的日志不算通过 |

## 七、设计原则（为什么这样拆）

- **persona 短、AGENTS.md 中、skills 深**：persona 每次请求都付费，只放最高频纪律；项目契约放 AGENTS.md；子系统细节按需加载。
- **一个技能一个子系统**：路由靠 description 的触发条件；总入口只做分诊，不复制细节，避免多处口径漂移。
- **证据优先于记忆**：技能里给的是"去哪里找 + 怎么验证"，不是把会过期的状态数字写死。
- **模式不是自动流水线**：它约束工作方式与证据，不替人决定里程碑优先级；下一步始终以 `docs/现状与待办.md` 为准。

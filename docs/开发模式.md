# 开发模式与项目技能

更新：2026-10-25。v1.1：完成度判据从「一次 CI 进程」改为「同 treeHash 的可续跑台账」，全量 CI 改由计划任务脱会话执行，新增止损/汇报节奏、env-check、check-docs、套件分层与六态词汇。

本仓库配了一套 **DSH Agent preset（开发模式）＋ 项目技能 ＋ 项目契约**，让 AI 代理在这个仓库里按项目既有纪律工作：
先读证据、按切片交付、守住不变量、不把提案当已实装。

## 一、组成

| 位置 | 是什么 | 生效方式 |
| --- | --- | --- |
| `.dsh/agent-preset/` | DSH bundle（`@local/dsh-xinglu-preset`），声明 Agent preset「苔芽农场开发」（id `xinglu-dev`） | 已安装进当前 DSH profile；**改完要重装**，新会话才生效 |
| `.dsh/skills/` | 10 个项目技能（`xinglu-*`） | 文件系统技能目录，改完立即热更新（新一步的 skill 目录会刷新） |
| `AGENTS.md` | 项目契约（所有会话自动加载） | 编辑后新一次读取/新会话生效 |
| `docs/开发模式.md` | 本说明 | — |

配套工具（2026-10-25 起是模式的一部分，不是可选项）：

| 工具 | 作用 | 什么时候用 |
| --- | --- | --- |
| `tests/env-check.mjs` | 环境预检：chromium 能否启动/EPERM、是否已有浏览器作业、心跳是否中断、output 可写、PS 编码、git dirty | 开工第一条、长跑前 |
| `tests/run-ci.mjs` | 统一 CI 入口；阶段结果写入 `output/ci-journal.json`，支持 `--quick/--resume/--from=/--stop-after=/--status/--dump-steps` | 快速层、续跑、观察 |
| `tests/gate-detached.ps1` | 把全量 CI 交给 Windows 计划任务 `MossFarmCI`，脱出会话 job 树 | `-Action start/install/status/stop/uninstall` |
| `tests/check-docs.mjs` | 交付前文档机检：数字对台账、退出码 0 要有 exit 证据、生成区手改、日期-提交一致 | `--regen`（重新生成再比对） |

模式里包含：项目 persona（先事实后动手、切片闭环、证据三层、硬约束、技能路由、长跑与止损）、`AGENTS.md` 自动加载、
Windows PowerShell（本机是 5.1，没有 `pwsh`；读 UTF-8 日志必须 `-Encoding utf8`）与文件工具、`skill` 加载器、计划模式（项目定制版）、
目标/todo、子代理与 workflow、后台 job、web、present。
`plugin_manager` 在模式内保持关闭（与 Standard 一致），避免在业务会话里误改 profile。

## 二、怎么用

1. **选择模式**：新建任务时在模式选择器里选「苔芽农场开发」；或在 Settings 的 Agent Preset 列表里把它设为新任务默认。
   已存在的会话**不会**自动切换模式（保留创建时的组合）。
2. **权限建议**：跑 Playwright / 完整 CI 的会话建议用 Full access 或对本机放行；Windows 沙箱下 Playwright 可能
   `spawn EPERM`，那是环境拒绝，不是回归。
3. **开工顺序**：先跑 `node tests/env-check.mjs`，不合格按提示修；再加载 `xinglu-project-orientation`（它告诉你先读哪几份文档、按 P0—P4 选题），
   有长跑在跑或中断过就看 `node tests/run-ci.mjs --status`；然后按任务加载子系统技能（钱/存档/场景/剧情/渲染/UI/套件/收口）。
4. **全量 CI 不要占会话**：跑全量用 `powershell -NoProfile -ExecutionPolicy Bypass -File tests\gate-detached.ps1 -Action start`，会话只 `--status` 观察。
   判据是台账（同 treeHash 103 条全绿）＋末行「两层全部通过。」＋退出码 0，不是「这一次进程跑完」。
5. **中途可交付**：任一验证单元通过就同步/提交，不等全量；长跑期间每 15–20 分钟或每个阶段簇报一次进度。

## 三、判据与长跑

为什么改（2026-10-25 复盘）：旧模式把「诚实」做硬、把「可恢复」做软——判据绑在一条 75–80 分钟、会被环境掐断的进程上，
缺台账/续跑/止损/机检/汇报节奏，结果 120/123、0 失败也只能写「未通过」。近 5 次全量 CI 有 4 次没产出判据
（环境每 2–7 小时杀一次会话 job 树）。另外 8 份手写事实源互相矛盾，有文档把没有退出码行的日志写成「退出码 0」，
生成区被手改无法机检，自然路线项数随分支漂移（279/291/289），PowerShell 5.1 把 UTF-8 日志里的 96 项误读成 36 项。

v1.1 的判据：

- **一个 treeHash 一本台账**：`output/ci-journal.json` 记录 121 条阶段（5 快速＋97 浏览器＋19 单文件）的完成与结果；
  同一 treeHash 全绿＋末行「两层全部通过。」＋`output/ci-exit.log` 的退出码 0 才算通过。允许跨多次进程。
- **可续跑**：中断时台账只记已完成步骤；`--resume` 接着跑；`--status` 报 x/117、ETA、当前步骤、失败、未跑。
- **禁止两种错**：无末行就宣布通过；从中断处从头重跑。
- **treeHash 变了台账作废**：跑之前冻结源码/测试/产物；中断后先 `--resume`，别改代码——改了就得重新记账。
- **分批**：`--stop-after=N` 只跑 N 个阶段（验证续跑/分批），`--from=<step-id>` 从某步重跑，`--dump-steps` 查 step-id。
- **脱会话**：`gate-detached.ps1 -Action start` 触发计划任务 `MossFarmCI`（按需任务、无触发器，跑 `node tests\run-ci.mjs --resume`；首次用先 `-Action install` 注册）；
  心跳 `output/ci-heartbeat.json`（pid/step/updatedAt）判断进程死活；`-Action status` 汇总台账＋心跳＋退出码；
  `-Action stop` 连心跳里的 pid 子树一起杀。**不要用会话 `run_in_background` 的 pwsh job 承担全量 CI**（会随 harness 重启被杀）。

## 四、止损与汇报

- **连续 2 次非产品中断**（无末行、心跳停、进程没了）→ 必须改 OS 级执行方式（`gate-detached.ps1`）并 `--resume`。
- **连续 3 次** → 必须拆层出证据：写「分层通过 x/109」＋各步日志，不得再从头重跑。
- 产品/断言失败仍按原规则修，不靠改断言变绿；修完 treeHash 变，重新记账。
- 长跑期间每 15–20 分钟或每个阶段簇用 `--status` 报一次：**x/109、ETA、风险、现在能交什么**。禁止连续多轮只「等 10 分钟」。

## 五、文档机检

- 交付前必须跑 `node tests/check-docs.mjs --regen`：数字对台账/`--dump-steps` 计算值、「退出码 0」「两层全部通过」必须有 exit 证据、
  `docs/feature-status.md` 生成区手改即红、提交哈希能在 git 里解析、日期不超前。
- 它会启动 Chromium 读生成器（`--regen`），**必须串行，别和全量 CI 并行**。
- 红了先查是数字写错还是证据没落盘；不能靠改文档描述绕过。`docs/feature-status.md` 仍由生成器生成，人工节必须保留。

## 六、套件分层

- **夹具套件**：确定性（固定 seed/预置状态），精确项数可写进文档（如某专项 195 项通过）。
- **自然入口套件**：只断言「任务全通/状态推进/无浏览器错误」，项数当元数据、不进正文——项数会随分支漂移（279/291/289）。
- 时间/体力预算类算术断言下沉快速夹具，不让约 27 分钟的自然路线承担精准算术。
- 无论哪层，挂进 `run-ci` 后由台账记录，不要求整轮一次跑完。

## 八、维护

### 改技能

直接编辑 `.dsh/skills/<name>/SKILL.md` 即可，下一步会刷新技能目录。约定：

- 目录名 kebab-case，`SKILL.md` 首部 YAML frontmatter 必须有 `name` 与 `description`（description 写清触发条件）。
- 正文 < 8192 字符（超过会被 tool-result pruner 截断）；长表格/配方放 `references/`，用相对路径引用。
- 数字与行号是快照，改了代码后用 grep 复核；跨技能重复的事实放到 `xinglu-code-navigation`，别两处各写一份。

### 改模式（preset）

模式是一个 bundle patch：`.dsh/agent-preset/cordis.patch.yml`。改完后必须**重新安装**并让新会话生效：

```
plugin_manager(action="install_bundle", target="C:\\Users\\22079\\Documents\\ChatGPT\\星露谷\\.dsh\\agent-preset")
```

（也可以在 Web 的 Plugins 页重新安装该本地 bundle。）验证：

- `plugin_manager(list_bundles)` 中 `@local/dsh-xinglu-preset` 为 `enabled/installed/removable`，rows 为 `preset-xinglu-dev`；
- `cordis_inspect_query(host, Config, listConfigs, {name:"@deepseek-ai/dsh-agent-preset"})` 中出现 `include:preset-xinglu-dev`；
- 新建一个会话选择「苔芽农场开发」，确认 persona/技能/工具都可用（现有会话不会被改写）。

卸载：`plugin_manager(action="remove_bundle", target="@local/dsh-xinglu-preset")`。项目文件不影响已运行的会话。

### 改项目契约

`AGENTS.md` 会自动注入所有会话；它和技能冲突时以更具体的技能/直接用户指令为准。改动后请同步本文件与技能里的引用。

## 十、故障排查

| 现象 | 处理 |
| --- | --- |
| 模式选择器里没有「苔芽农场开发」 | 确认 bundle 已安装且 preset 行激活；重装 bundle；刷新页面 |
| 新会话没有 persona/工具 | 可能选错模式（现有会话不切换）；新建会话再选 |
| 技能列表里少了项目技能 | 确认会话工作目录是仓库根（`.git` 所在处）；技能在 `.dsh/skills/`，只扫一层目录 |
| 技能内容改了但会话没变 | 技能目录会在下一次 pre-step 刷新；已加载过的正文是历史消息，需要重新加载 |
| preset 改了但没生效 | 必须重装 bundle 且新建会话；现有会话保留旧组合 |
| Playwright 报 `spawn EPERM` | Windows 沙箱拒绝命名管道，换 Full access；不是代码回归 |
| 完整 CI 看起来"绿" | 认台账（同 treeHash 121 阶段全绿）＋末行「两层全部通过。」＋`output/ci-exit.log` 退出码 0；中断/仍在增长的日志不算通过 |
| 会话后台 job 被 harness 重启连坐 | 全量 CI 不用 `run_in_background`；`powershell -NoProfile -ExecutionPolicy Bypass -File tests\gate-detached.ps1 -Action start` 交给计划任务 `MossFarmCI` |
| 不知道 CI 进程死没死 | 看 `output/ci-heartbeat.json` 的 `updatedAt`/`pid`；心跳停=进程没了；`-Action status` 汇总 x/117 |
| `--resume` 不续跑/台账归零 | 代码、测试或产物变了，treeHash 就变、旧台账作废；恢复冻结后再跑，别在中途改代码 |
| PowerShell 5.1 读日志乱码/项数不对 | 用 `read` 工具或 `Get-Content -Encoding utf8`；曾把 96 项读成 36 项 |
| 计划任务注册失败（权限/策略） | `-Action install` 需要创建任务的权限；失败就在任务计划程序手工建一个按需任务，动作是 `node <仓库>\tests\run-ci.mjs --resume` |
| `gate-detached.ps1` 被拒（未签名/执行策略） | 命令必须带 `-NoProfile -ExecutionPolicy Bypass -File`；裸 `powershell -File` 会报「not digitally signed」 |

## 十一、设计原则（为什么这样拆）

- **persona 短、AGENTS.md 中、skills 深**：persona 每次请求都付费，只放最高频纪律；项目契约放 AGENTS.md；子系统细节按需加载。
- **一个技能一个子系统**：路由靠 description 的触发条件；总入口只做分诊，不复制细节，避免多处口径漂移。
- **证据优先于记忆**：技能里给的是"去哪里找 + 怎么验证"，不是把会过期的状态数字写死。
- **模式不是自动流水线**：它约束工作方式与证据，不替人决定里程碑优先级；下一步始终以 `docs/现状与待办.md` 为准。
- **完成度是可续跑的台账，不是一次进程**：判据绑在 treeHash 的 109 条阶段上，进程只是执行器；进程会被环境杀掉，台账不会。

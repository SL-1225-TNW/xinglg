## 本期交付目标

从自然新档完成一条工程职业：小镇维修 → 矿山或磨坊实践 → 有范围的认证 → 公共工程立项 → 预算与施工 → 预警与处理 → 验收或失败恢复 → 持续维护。工程结束后，供水、运输和人物态度确实变化，玩家仍可回农场生活。

当前已有独立工程报告、即时事故两分支、岗位、一次150金预算和说明会。缺口是实际施工、按条件触发的预警、完整支出账、失败复查与持续职责。R2水泵值守是可复用的跨日责任入口，不等于完整职业。

### 落地形态（R3-A 已完成）

- 前置链核出三处问题。水利区通行原本要求采场、河港、磨坊**三份同时到手**，等于逼玩家先跑完全图；改为「矿山排水**或**磨坊维修任一验收通过」，两条路线都能解释，且不额外要求个人战斗。另保留「采场调查＋河港核验」这条独立开口，所以缺实践时也能进场看现场，只是领不到认证。
- 消掉一处真实重复判断：`extendedGateAllowed()` 与 `extendedSceneAllowed()` 各自抄了一份水利区口径，门口显示的开放条件和实际能不能进并不一致。两处现在读同一条规则，并把「工程已交付」收敛到 `projectAcceptedFlag()`，不再用中途就会为真的 `waterworks.certified` 代表交付完成。
- 项目记录：`professionalLife.projects.riverbay_gate`，含 `phase`（有序编号）、`scheme`、`survey`、`opinions`、`build`、`mode`、`crew`、`funds`。**没有第二套布尔值** —— `phase` 与 `build` 就是进度本身，`waterworks` 的旧字段是单向镜像。
- 资金：机构拨付 150 金（一次）、闸件套装代购 24 金、班组日薪 40 金，各带稳定事务 ID（`riverbay:grant` / `riverbay:kit:<方案>` / `riverbay:wage:<第几道>`）。个人自愿补记走 `riverbay:donate`，从私房钱出账、单独记账；机构余额与个人钱包在界面与账本里分列。
- 预算数是算出来的：闸件套装 24 金 ＋ 日薪 40 金 × 保守方案三道工序 = 144 金，落在 150 金拨付内留 6 金余量；兼顾通航四道工序要 184 金，超出部分只能自愿补记 —— 这是刻意留的取舍，不是平衡没做完。
- 旧档迁移：读一次旧 `waterworks` 布尔值写进项目记录，之后由 `deriveWaterworksFromProject()` 单向写回，镜像层没有第二条写入口。三种旧档（已发证／已装闸件未验收／只读水尺）各有断言且往返幂等；旧档当年领过的 150 金记成 `legacy:grant` 已结算事务，不会再发一次。
- 联系人、认证范围、材料来源和下一步由 `engNextStepText()` 统一生成，今日安排、N 委托日志与角色经历三处共用同一份文案。

## R3-B：一项真实工程

首项建议沿用河湾／水利站的闸门与排水改造，复用现有场景和供水、货运效果，不另扩大地图。

- 正常流程：勘测 → 选方案 → 材料交接 → 施工 → 跨日试运行 → 验收 → 维护。
- 提供保守排水与兼顾通航两种方案。确认前显示成本、施工日数、影响对象与风险，至少在供水或货运上产生可测量的差异。
- 现场勘测、交接、施工与复核都有真实位置和明确耗时；关键工序不能在远处直接完成。
- 自己施工与委托施工使用同一份工程进度。委托显示人员、经费、完成日、停工原因和领取／验收入口，不使用一个“委托成功”布尔值冒充流程。
- 交付后改变设备或现场外观，地区服务读取已验收效果；效果不得因打开面板、重载或重复签字叠加。

通过条件：至少一条方案完整施工并跨日验收；两方案后果真实不同；背包满、缺料、钱不足和日终不足均不留下半笔事务。

### 落地形态（R3-B 已完成）

流程落在河湾闸门与引水改造上，沿用既有水利站场景与供水、货运效果，没有扩图。

| 阶段 | 在哪里做 | 做什么 |
| --- | --- | --- |
| 勘测 | 坝顶水尺 (20,18)、东岸坡脚 (21,20)、下游淤积段 (21,16) | 三处各读一次。读数按当天天况判定并存进项目记录：雨天水位 3 级、坡脚开裂、淤积偏厚（基础风险 4）；晴天则相反（基础风险 1） |
| 认证 | 水利站 · 闸门控制室 (8,6) | 须先完成矿山排水或磨坊维修任一实践。认证范围分三档：无 → 基础 → 可主持公共工程 |
| 定方案 | 闸门控制室 | 说明会就是方案确认，须三方意见与机构拨付同时到位，确认前列出工序数、金费与基础风险 |
| 材料 | 坝顶水尺或控制室 | 石料自采自运（采场 → 测量棚 → 河港 → 凭核验运单签收），闸件套装由项目账代购，埋件铁锭自己带 |
| 施工 | 闸基工作面 (22,14) | 亲自施工（花时间体力）或委托班组（40 金／工日，每天一道） |
| 试运行 | 闸基工作面封闸 | 必须跨过一个游戏夜晚才能验收 |
| 验收 | 坝顶水尺或控制室 | 签名后地区服务才按方案读取效果，坝体步道口画出新闸 |
| 养护 | 坝顶水尺或控制室 | 隔一天可做一次，按周期出现，不强制每日签到 |

- **两种方案的后果真的不同**：保守排水让石料／互市货运 +20 分钟、牧场试种田自动供水；兼顾通航 −10 分钟、农田分时供水。矿场、牧场、河港三方意见在定案前必须记录齐全。
- **自建与委托共用同一份工程进度**（`pj.build`），区别只是花钱方式与节奏；第一道工序落下后不能换方式。班组因经费停工时给两条保底：自愿补记**实际差额**（不是整天工钱），或把剩下的工序改为自己施工接手 —— 不会把角色堵死。
- **区域效果只由已验收结果驱动**：验收前地区口径最多是事故期间的应急处置，验收后才由工程方案取代，两者写在不同字段，不会互相覆盖；重开面板、重载存档、重复签字都不会叠加。
- 失败边界都有断言：缺铁锭、钱包为零、远程操作都不会留下半笔事务（背包、金币、时间、项目记录四件一起比对）。

## R3-C：预警、失败恢复与持续职责

- 风险来自已保存的勘测、工序、维护状态及游戏天气／日期。先显示渗水、销钉松动或水位异常，再到需要决策的节点；打开报告不能凭空制造事故。
- 玩家可检查、停工、加固或承担方案代价。妥善预防能直接验收与取得岗位评价，不要求先发生事故才能晋升。
- 漏检或处理不当进入明确的部分失败：记录受影响服务、缺失工序和恢复成本，提供应急处置 → 补修 → 复查 → 结案路线。
- 维修和求助有保底办法，不以无限罚款或唯一材料丢失堵死角色。离开地区、读档和洗点都保留已接责任。
- 首轮岗位只负责这一类工程，持续维护按周期出现，不强制每日签到。允许解释、交接和退出；完整任期与行政权留待R5。
- 预警、待复查和维护出现在今日安排与N记录中，防止玩家只能靠翻旧对白找责任。

通过条件：正常预防、事故恢复、途中离开再回来三条路线均走通；关键事件不在后台或读档时偷偷结案。

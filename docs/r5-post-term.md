# R5-A 实施设计：河湾闸门岗位试任期

更新：2026-10-19。本文是待实施设计，代码尚未接入。总顺序见 [R5 实施规划](r5-plan.md)。

目标是用一个玩家能自然走完的纵向切片，满足总规 §13 的六个要素：工作范围、预算、考核、期限、交接与辞职。它不是七职业通用框架。

## 一、复用现状

R3 已有 `pj.duty` 养护责任，包含 `none / active / handed / released` 状态、3 天检视周期、检视与评价计数、延期、逾期、交接和退出。水利控制室与风铃磨坊机房可操作，河港船务屋与船闸值守室只读。

R5-A 保留这套实时责任账，不复制“今天是否该检视”这一事实。新增内容只回答：玩家当前处于哪段正式任期、预算用了多少、期末如何结束。

## 二、关键优化决定

1. **首任期为 28 天，不是 112 天。** 一个季节足以覆盖 9—10 个三日周期，玩家能在自然试玩中看到期末；完整年度任期留待后续真实需要。
2. **岗位预算是真正有限的 120 金。** 每次合格检视支付 12 金，按登记时既有 `nextDay` 的位置最多结算 10 次；未使用预算留在结案记录，不转入玩家钱包。
3. **不预建空官职和荣誉容器。** 本轮只增加真实使用的专业任期数据。
4. **交接压缩为两步。** 在任期面板申请，去石灰采场由玛尔确认后直接完成，不要求玩家再原路返回按第三个按钮。
5. **到期进入待评状态。** 不继续无限生成无任期义务和津贴；玩家看完报告后选择续任、交接或辞职。未处理的安全事实仍保留。
6. **辞职始终是退出权。** 未清事项会写入结案并留在世界账本，但不把玩家永久锁在岗位上。

## 三、事实归属与数据结构

### 3.1 唯一事实

| 事实 | 权威记录 |
| --- | --- |
| 当前是否承担养护、下次检视日、延期与逾期 | 既有 `pj.duty` |
| 任期起止、阶段、岗位预算、结案报告 | `professionalLife.postTerms[]` |
| 玩家现金 | 既有钱包字段 |
| 工程专款 | 既有 `pj.funds`，与岗位预算严格分开 |

`postTerms[]` 的“条目”只追加；当前条目在任期内可更新预算支出，结案后冻结。这里不再声称整条记录从创建起完全不可变。

### 3.2 任期记录

```js
{
  id: 'post:gatekeeper:1',
  post: 'gatekeeper',
  phase: 'active',              // active | review_due | closed
  startDay: 0,
  reviewDay: 28,                // startDay + 28；当天起进入 review_due
  scope: ['销钉渗水', '闸缝间隙', '岸坡淤积'],
  baseline: {                   // 开岗时抄一次，用于计算本任期增量
    done: 0, evalCount: 0, deferCount: 0, overdue: 0
  },
  budget: {
    appropriated: 120,
    spent: 0,
    tx: {}                      // 事务 ID -> 金额
  },
  close: null                   // 结案后写 day / reason / successor / stats / rating
}
```

`pj.duty` 只需增加当前 `termId` 和交接申请信息。任期统计不在两处持续累加：显示和结案时用 `pj.duty` 当前累计减去 `baseline` 得到本任期增量，结案后只读 `close.stats`。

## 四、生命周期

```text
无任期 ──登记试任──> active ──到第 28 天──> review_due
                       │                         ├──续任──> 结案并追加新任期
                       │                         ├──申请交接──> 玛尔确认──> handed
                       └──随时辞职───────────────┴──────────> released
```

- 登记当天是第 1 个任职日，`reviewDay = startDay + 28`。
- 登记不重置既有 `duty.nextDay`，避免通过反复登记刷新检视期限。
- 只有到期日在 `reviewDay` 之前的检视周期可以结算本期津贴。
- `review_due` 不再产生新周期和新津贴；面板优先显示期末报告与三个去向。
- 续任先封存旧记录，再追加新记录；不追溯补发，不修改旧记录。
- 交接或辞职封存当前记录，同时沿用 R3 的 `handed / released` 结果。
- 未处理的安全事件、逾期事实和工程状态不会因结案被清除。

## 五、预算与津贴

| 情形 | 玩家钱包 | 岗位预算 | 记录 |
| --- | ---: | ---: | --- |
| 任期内按期完成合格周期 | +12 | −12 | 写唯一事务 ID |
| 逾期后补做 | 0 | 0 | 写入本期统计 |
| 申请延期 | 0 | 0 | 写入本期统计 |
| 重复点击、重载后重复结算 | 0 | 0 | 复读原事务 |
| 到期待评后继续打开面板 | 0 | 0 | 不生成新周期 |

事务 ID 使用“任期 ID + 到期日”，而不是点击次数，例如 `post:gatekeeper:1:due:15`。支付前同时检查：任期为 `active`、该到期日在 `reviewDay` 前、评价合格、事务不存在、剩余预算不少于 12 金。

机构预算显示“核定 120／已用 N／结余 N”，结余只归档，不自动发给玩家，也不混入 `pj.funds`。

## 六、期末考核

考核只用本任期增量，不读取历史任期：

| 评级 | 条件 | 本轮后果 |
| --- | --- | --- |
| 稳任 | 无逾期，延期不超过 1 次，完成全部已到期周期 | 可续任；写入档案 |
| 有条件 | 逾期不超过 1 次，延期不超过 2 次 | 可续任；报告标出缺口 |
| 未完成 | 其余情况 | 本轮仍允许续任、交接或辞职；只记录事实 |

R5-A 不给称号、奖金或惩罚，也不制造一个没有真实后果却声称可听证的入口。R5-B 只在后续出现真实款项或合同处置时接入复核。

## 七、交接与辞职

### 交接

1. 玩家在水利控制室或磨坊任期面板选择“申请交接”。面板列出未清安全事项和逾期事实，并指向石灰采场玛尔。
2. 玛尔处显示同一份摘要。玩家确认后直接完成交接、封存任期并将 `duty.status` 置为 `handed`。

交接确认使用唯一事务 ID；重复点击和读档不会封存两次。未处理世界事实不因交接消失。

### 辞职

辞职在任期面板一次确认后完成，不需要继任者同意。确认框必须说明未清事项仍会留档；完成后封存任期并将 `duty.status` 置为 `released`。

## 八、玩家入口

| 地点 | 功能 |
| --- | --- |
| 水利站 · 闸门控制室 | 登记、预算、期限、考核预览、续任、申请交接、辞职 |
| 风铃磨坊机房 | 同源操作面板，使用马丁的地点说明 |
| 下游河港 · 船务屋 | 只读当前阶段、期限和预算 |
| 河港船闸 · 值守室 | 只读当前阶段、期限和预算 |
| 石灰采场 · 玛尔 | 只在已申请交接时出现确认入口 |

今日安排、委托日志和角色经历继续复用同一个“下一件事”生成函数。`review_due` 时，期末选择优先于普通检视提示。

## 九、旧档兼容

- 缺少 `postTerms` 时归一化为 `[]`，不自动伪造历史。
- 旧档中 `duty.status === 'active'` 且没有任期时，原有三日养护照常运行，面板显示“尚未登记正式试任期”。
- 玩家可从当天登记 28 天试任期；不追溯津贴、考核或预算。
- 结案记录坏值只做安全归一化，不重新打开已封存任期。
- 当前任期引用丢失时，降级为“无正式任期的既有养护责任”，不得自动发钱。

## 十、实施顺序

1. 先为专业生活账本加入 `postTerms` 的创建、归一化和查找；不加空官职／荣誉字段。
2. 接入任期登记、28 天阶段计算、基线差值和结案冻结。
3. 接入 120 金预算、12 金合格津贴和幂等事务。
4. 接入期末报告、续任、两步交接与单步辞职。
5. 同步四处面板、今日安排、委托日志和角色经历。
6. 新增 `tests/run-r5-post-term.mjs`，先跑源码，再重建并验证单文件版。
7. 回归 R3 养护、R4 外出／照料、旧档和主线；最后同步状态文档。

实现中按功能切片提交，不按文件拆提交；每个提交都应保持可运行和可回退。

## 十一、验收清单

### 规则与存档

- 28 天边界、`active / review_due / closed` 转换正确。
- 只有合法周期支付 12 金，单任期最多 120 金，预算与工程专款不串账。
- 连点、重载、重复结案、续任后重开旧记录均幂等。
- 任期统计按基线差值计算，旧任期封存后不再变化。
- 旧档、坏引用和缺字段不会自动获得任期或津贴。

### 玩家流程

- 从既有养护入口真实点击登记，不靠内部函数造任期。
- 玩家能提前看见期限、工作范围、预算和本期表现。
- 到期后能从界面完成续任、交接或辞职，三条都能继续游戏。
- 玛尔只在申请交接后出现确认，确认一次即完成。
- 390×844 与 844×390 下无横向溢出，主要按钮可触达。

### 相邻回归

- R3 磨坊养护与湿地复查全绿。
- R4 外出工作、农场照料和存档不变式全绿。
- 源码与单文件版使用同一规则，主线回归通过。

## 十二、停止条件

出现以下任一情况时不继续扩写 R5-A：岗位预算能被重复领取、封存记录可变、旧档被自动登记、辞职被安全事件永久锁死、R3 三日养护失效、单文件版与源码结果不同。先修复并补回归，再进入 R5-C。

# R3-C2：岗位评价双路线与周期养护责任

2026-10-15，本地实现，接在 R3-C1 之后。本轮解除「必须先发生事故才能晋升」的依赖，把验收后的养护从可重复点的按钮改成周期责任，并补上延期、交接与退出。R3-C2 至此收口；R3-D 与 R4 仍未开始。

## 一、岗位评价有两条来源

原来 `normalizeSave` 里写着「没处置事故不可能有岗位」：读档时凡是 `stage>=2` 却没有 `incident` 的存档，一律被压回 stage 1 并清空岗位。也就是说，即使做出一条预防路线，只要没先出事，读一次档就前功尽弃。这条硬依赖已经删掉。

现在岗位评价来自 `eng.postEval`，两条路线互不覆盖：

- **预防**：在坝顶水尺的旧闸检修口做汛前预防性加固（备料 45 分钟／2 体力，或不用材料 120 分钟／5 体力），直接取得岗位评价。
- **事故**：原有的夜雨事故处置保留，记为事故来源。

`preventive` 与 `postEval` 都进存档归一化；`postEval` 只能指向真实存在的那一条，指错了会被压回空值。已经发生过事故的旧档照旧保留 `incident`，不会被改判成预防。

机构拨付、说明会与施工链没有因此放松：预算仍要岗位、方案仍要三方意见与到账拨付。

## 二、养护是周期责任

旧口径是「隔一天可做一次，每次加互信并涨资历」——那是个可以反复点的按钮。现在验收当日起接下一份周期责任 `project.duty`：每 3 天一个检视周期，面板固定显示**下次检视日、工作范围、联系人**（诺娅·水利控制室）。

- 检视只在到期后出现，点了就把下次检视日推进一个周期。
- **评价按走完一个周期结算**：连续按期检视 3 次才结算 1 次资历与互信，不是每点一次涨一次。
- **逾期补做只留记录，不发评价**，并把逾期次数记进档案；逾期时申请延期还会另存当时的逾期天数。离乡 37 天回来，面板就如实显示逾期 37 天。
- `duty` 只在验收之后存在；未验收的旧档不追溯生成岗位责任。
- 已经验收、却没有责任记录的旧档（R3-C2 之前）会**接回养护循环**，从它最后一次养护日按周期起算——否则这类存档会永久失去养护功能。不凭空补检视次数，也不追溯改写已发生的处置。

## 三、延期、交接与退出

- **延期**一次推一个周期，累计 3 次封顶。封顶后面板直接告诉玩家：要么交接，要么退出，不能无限拖。每次延期都留下天数与理由，面板与角色经历里都查得到。
- **交接**给继任工程员（玛尔，石灰采场工头），**退出**则是主动结束岗位。
- 两个入口的前置都是「安全记录已处理完」。闸门还有未处理事件时，入口仍在（玩家知道有这个选项），但点击会被拒绝并说明原因——**交班不清账**。离岗之后 `safety` 记录原样留在工程里，继任人与你自己的检视、延期、逾期记录都可查。

## 四、三种已发生结果，各说各的

`pj.safety.route` 记一件事最后怎么收的：`prevent`（预警期主动加固）、`recover`（漏检后应急控水＋补修＋隔夜复查）、`normal`（低风险正常跨夜）。三者互不替代，读档后据此还原真实经过。

- 诺娅（`water_engineer`）与马丁（`mill_martin`）走对话线，两种结果两种说法，彼此不同。
- 柯里是议事员的判断口径，**不是一个可对话的 NPC**（`councilor` 那段定义嵌在未被使用的字面量里，运行时不注册），所以他的口径写在工程面板与项目记录里，而不是硬造一个对话对象。

没有已发生处置时不硬塞任何结论。

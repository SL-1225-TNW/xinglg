## 一、R5 的完成定义

R5 不再扩地图或堆职业数量，而是把已经存在的责任、资金和授权补成可玩的制度闭环。完成时玩家应能证明五件事：

1. 资金不能通过同一物品的买入、兑付或典当即时增殖。
2. 至少一个专业岗位有范围、有限预算、期限、考核、续任、交接和辞职。
3. 至少一类对玩家不利的正式决定可以查看证据、申请复核并得到有限结果。
4. 军事首轮从自愿接受到合法授权、准备、行动、撤离和复盘没有权限跳步。
5. 源码、单文件版、旧档、键鼠和手机触控使用同一事实，发布产物与验收产物一致。

这五项全部通过才称为“R5 完成”。单个脚本全绿只代表对应切片完成。

## 二、优先级调整

原方案把金融放在岗位、听证和军事之后，风险顺序不合理。当前代码存在待实跑确认的公债即时套利：认购价、银行兑付价和典当价来自不同口径，可能形成无限金币。R5 改为：

**R5-0 经济止血 → R5-A 岗位试任期 → R5-C 金融样板 → R5-B 有限复核 → R5-D 军事权限整理 → R5-E 发布收口。**

- 先处理会破坏整个经济的发布阻断项。
- 先做一个能自然走完的 28 天岗位试任期，不直接设计七职业通用框架。
- 复核必须针对真实存在且会产生影响的决定，因此放在岗位和金融样板之后。
- 军事只整理已有首轮流程和授权，不借 R5 扩写战役内容。

## 四、R5-0 的决策边界

静态读码显示同一张 `bond` 可能出现三种单价：市政厅认购 150 金、银行按物品售价倍数兑付约 232 金、典当 420 金。`bill`、`share_cert`、`warehouse_deed` 还共用部分兑付逻辑。实施时先用真实界面确认，不根据静态计算直接改数值。

确认后只建立一份权威报价资料，分别表达：

- **发行价**：玩家取得票据的成本。
- **票面／兑付条件**：只有满足期限或任务条件才可兑付。
- **典当估值**：不得高于无条件可回购成本，且同一票据不能同时被兑付和典当。
- **交易记录**：取得来源、成本、处置方式和事务 ID 可追溯。

R5-0 只堵漏洞并统一解释，不顺手制作完整银行家职业。

## 六、范围控制

R5 明确不做：七职业全部任期、市长或议会玩法、官职与荣誉空壳、爵位封授、银行危机、宏观市场、复杂军事组织、跨封国长途旅行、14／28 天离农计划、25 级和后续十五天赋。

特别说明：数据结构只为本次实际内容服务。不会为了“以后也许会有”而预建空的 `offices`、`honors` 或通用制度框架；等真实玩法进入实施再迁移。

1. 实跑并修复 R5-0，先取得经济安全基线。

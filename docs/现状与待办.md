### 4. 工具链：全量 CI 再压一轮（浏览器层分片并行）

第五幕阶段口径为 105 的历史轮次全量仍在 100 分钟量级，当时底座是浏览器层 89 条（约 85 分，其中第四幕自然轮独占 27.5 分）。再压到 45 分钟内只有分片并行一条路。设计与风险先写在这里，下一轮直接开工：

- **做法**：浏览器层按 N 个 worker 分片；每个 worker 独立 chromium 实例（独立 userDataDir）、独立步骤日志目录（`output/ci-step-logs/w<N>/`）、独立台账文件（`output/ci-journal-w<N>.json`），主进程只做汇总与收口判据。
- **为什么当年有 "Page crashed" 假回归**：两个作业共享同一浏览器／同一 profile，或同写 `output/`。分片时把 profile 与输出目录都隔离即可，串行规则改成「同一 worker 内串行、worker 之间可并行」，默认并行度 2（保守），实测稳定后升 4。
- **风险**：内存（本机 32 GB，每个 chromium 约 1–2 GB，4 worker 可承受）；失败要能区分「某分片失败」与「整体失败」；续跑要按 (worker, step) 记账，不能只看阶段 id。
- **验收**：改造后连跑两轮全量——两轮按届时阶段清单全绿、总耗时进 45 分钟、没有新增假回归；改造本身走代码／测试／文档分笔提交，并同步契约 §8 与 §11。
